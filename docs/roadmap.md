# Remaining product work

Track only work for the supported official Desktop-owned route. Do not reopen accepted
basic file reads, Web/Native switching, ordinary profile restoration or normal maintenance
cleanup without new failure evidence. Fixture, installed and user-observed acceptance have
different scopes. See [compatibility boundaries](web-native-compatibility-gates.md).

## Current product and release checks

- **Consumer tool ownership.** Turn the bounded local host-policy setup into an explicit,
  install-owned consumer integration where supported. Resolve exact installed plugin IDs,
  manifest server names and account-app sources; preserve ordinary Chat and independent
  Web-worker connections. Do not disable unrelated apps or infer the active model from prose.
- **Web failure and control paths.** Verify quota/model transitions, stream failure,
  uncertain submission, exact cancellation and original Goal completion on disposable tasks
  using the current route. Preserve accepted effects and original requests; do not resend
  settled turns or add a coordinator, poller, retry scheduler or second Goal engine.
- **Consumer lifecycle.** In a disposable OS account or VM, complete clean installation,
  host authorization, a harmless file read, actual repair/removal and keep-data reinstall.
  Existing fixtures and installed read-only maintenance do not prove destructive consumer
  acceptance. Keep account-plugin removal separate from local application removal.
- **Interrupted signed updates.** Exercise interruption during package replacement and
  service restoration in that controlled environment. Normal update/profile restoration and
  the disposable UI-exit test do not prove every signed-install recovery case. Reconcile
  existing transition receipts instead of repeating apply or reusing lost approval.
- **Resources and platform support.** Measure installed disk/cache residue and idle
  CPU/wakeups under representative use, plus restart continuity. The source can build
  Windows and Linux payloads from another OS. Verify real service registration, updates,
  removal and workspace identity on both target systems.
  Preserve active work, unresolved operations and recovery material when testing cleanup.
- **Physical device isolation.** On two owned computers sharing an account, use separate
  sentinel files and one local service offline. Verify local tools never discover or fall
  back to the other computer. Isolated service tests are not physical-device acceptance.


## External contracts and explicit limits

- **Native transport independence with same-chat switching.** Official Desktop ownership
  does not remove the current Native inference dependency on Tela's base URL. Preserve the
  user's same-chat Native/Web workflow; a different-provider chat is not an accepted substitute.
  Validate supported per-model routing or host provider transition before removing the composite
  route. Do not add another engine, automatic config switching or provider-history migration.

- **Cross-profile delegation control.** The retired external session manager could
  select a profile for thread creation and continuation. The current official
  host tools expose no Desktop-profile selector, and Plura's target lifecycle
  does not provide thread creation. Preserve this user capability as unfinished:
  connect supported profile-scoped create/continue/interrupt control with exact
  ownership before advertising cross-profile dispatch. Do not restore the old
  engine, job manager, private provider or history handoff as a substitute.

- **Per-profile Web delegation capacity.** The requested default is 3 concurrent
  child tasks per profile, user-adjustable but capped by the official app's maximum.
  The current Desktop-owned Responses route receives tasks after the official host
  admits them; it has no verified atomic pre-acceptance gate or readable host maximum.
  First establish a supported host enforcement/configuration and lifecycle contract
  across all child-creation routes. Do not revive discarded `webDelegationLimits`,
  present an inert numeric setting, or substitute a local scheduler. See
  [the admission boundary](web-delegation.md#concurrent-delegation-setting-pending-host-support).
- **Large Native-to-Web first transition.** The official engine can compact with the previous
  Native model before sending the first Web request. A supported destination-aware compaction
  override has not been established. Do not mask this by inflating Web limits, inventing a
  checkpoint or restoring a patched engine. See [context boundaries](context-continuity-contract.md#official-engine-pre-turn-compaction).
- **Unsupported tool and input extensions.** A Web answer does not authorize an original Native
  work-tool call. Such continuation needs authenticated structured intent and result receipts
  from the host. Attachments likewise need an exact supported upload/readback contract before
  they are advertised. Keep current text/Tela Chat operation distinct from these extensions.
- **Distribution and remote access.** Public distribution approval, supported local-host
  availability and authenticated remote exposure need their own acceptance. A remote connector
  is not a device-bound local plugin; do not claim the two have identical isolation.
- **Automatic delegated-chat management.** Explicit registration and exact-result
  acknowledgement now reach the existing service's next-due archive path in source.
  Source tests cover profile scope, current-turn clocks, writer deferral and restart;
  consumer Desktop installation/acceptance remains. Containers with Native child
  creation require user review because official archival cascades; an isolated source
  run verified leaf archival and preservation after manual restore.
  Newly executing Web children now notify that same registry; canonical lineage and
  first-turn checks exclude ordinary chats and later model switches. Other Native
  children and standalone Web chats require explicit enrollment. Work's **Manage Web task…**
  registers the exact chat, shows its latest saved answer and offers separate receipt confirmation.
  Automatic standalone enrollment still needs an official creation callback or a supported
  profile-scoped creation API. Retention is 12h from confirmed latest-answer collection,
  otherwise 7d from first enrollment; missing timestamps and new uncollected turns
  do not extend the fallback. Blocked chats stay registered and Work exposes a review list.
  Exact app-owned task stop and approval for affected descendants remain incomplete.
  One service timer reviews deferred records again
  after 12 hours without moving the archive deadline. Startup, profile changes and macOS
  Desktop exit/system wake can review sooner; no plugin hooks or approval are required.
  Existing install/repair/update refresh the owned source and an already installed enabled
  plugin through the official manager. Settings reports plugin state independently.
  Consumer Desktop acceptance, Windows/Linux host activation, exact per-thread unload and
  complete manual-restore observation remain. Automatic deletion stays disabled pending a
  restore-aware serialized contract: the installed engine still deletes a restored
  active thread through its unconditional delete API. Do not revive the retired engine
  or adopt ordinary chats by title.
  See [Web tasks](web-delegation.md).
