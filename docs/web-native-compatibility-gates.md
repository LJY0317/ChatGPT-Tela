# Web and Native compatibility boundaries

The official Desktop owns Native conversations, execution, tools, history and compaction.
Tela supplies a replaceable Web Responses route while preserving the built-in `openai`
provider identity. The supported setup is described in [official Desktop routing](official-desktop-provider.md).
Do not restore an external engine, private provider or old conversation-management layer.

## Accepted scope

- Installed macOS trials accepted real account-backed Web/Tela Chat file reads followed by
  an original Native command in the same `openai` conversation on both profiles. Basic
  Native app enumeration and the browser blank-tab lifecycle also have bounded user acceptance.
  These are model switches, not Web invocation of arbitrary original Native tools.
- Compatible Web follow-up retained its existing epoch/session and transferred a proven
  delta without another preparation-model call. This does not establish provider billing
  or guarantee the same result after arbitrary history, account or model changes.
- Standard local-plugin registration is recognized on both profiles. The user accepted basic
  read-only Chat file access after replacement. User-visible success is not an internal
  per-call transport/version certificate or a two-physical-device isolation proof.
- Normal signed update/profile restoration and installed read-only maintenance with automatic
  staging cleanup have bounded acceptance. A disposable production-delegate test with real
  Sparkle also proved normal deferral, UI-only exit and fresh startup without replaying an
  abandoned install callback. Actual replacement interruption and destructive consumer
  removal/reinstall remain separate checks.

Keep these scopes in future reviews; missing auxiliary presentation or old raw artifacts alone
must not turn a completed user workflow back into a failing task. Do not broaden the evidence
into universal platform, model, quota or tool compatibility.

## Authority, ownership and continuation

Request metadata supplies correlation, not Native authority. Only the host's original
advertised `get_goal` / `update_goal` functions may cross the authenticated supplied Goal
bridge. Their actual result determines Goal status; a final answer alone does not complete it.
Synthetic Goal fixtures do not prove an account-backed same-turn Goal workflow.
Original history readback requires its owner-bound source. HTTP disconnect alone neither
cancels accepted work nor proves the current Native turn is idle.

Bind an accepted Web operation to its actual send/answer lineage. Reuse compatible retained
context; preserve canonical current instructions, requests, unresolved effects and source-bound
checkpoint coverage. Uncertain acknowledgement does not authorize replay. See
[context continuity](context-continuity-contract.md) and [token efficiency](token-efficiency.md).
Human approval waiting, model generation, tool execution and final-result delivery remain
separate states. Diagnostic or progress visibility is not an execution receipt. Keep account,
profile, tool and physical-session ownership separate.

A general Web-to-original-Native work-tool bridge requires a host-authenticated structured
call intent and continuation receipt. Rendered Markdown, request IDs and model claims do
not provide them. A separately selected Native turn retains its original host tools.

## Host tool registration

Use the host's existing controls: ordinary MCP has `[mcp_servers.<server>] enabled = false`;
plugin MCP has `[plugins."<actual-plugin-id>".mcp_servers.<manifest-server>] enabled = false`.
Resolve IDs and server names from the actual installed source. Whole-plugin disablement
also affects its apps/skills; account-app routing is a different source of tools.
A local MCP toggle alone does not prove account-connected tools are suppressed.

The local policy trial is not an automatic consumer-install feature or per-model enforcement.
Before integrating it, prove that ordinary Chat and the independently owned Web connection
remain usable. Preserve unrelated plugins and account grants. Do not ship personal app IDs,
copy private capabilities or infer ownership from display names. Current plugin source uses
`.codex-plugin/plugin.json` and `.mcp.json`; retired manifest conversion is not a supported path.
See [Web task and tool policy](web-delegation.md).

## Official-engine limits

The engine may use the previous Native model to compact before a first transition to a
smaller Web context. This is outside ordinary Web checkpoint preparation. Do not advertise
zero Native preparation merely because Web preparation made zero calls. The exact boundary
and required upstream support are recorded in [context continuity](context-continuity-contract.md#official-engine-pre-turn-compaction).

An app being open does not establish active Native work. Unobservable activity must stay
an explicit observation limit, not an invented running task. Native route selection and
normal, user-authorized Desktop shutdown remain distinct from model/tool ownership.
See [update recovery](upgrade-recovery.md#macos-updates-through-sparkle).

The actionable release checks and external prerequisites live in [the roadmap](roadmap.md).
Do not recreate retired coordinators, private stdio attachment schemes or legacy chat recovery
to satisfy a historical trial. Investigate failures in supported conversations on their actual
current boundary, regardless of conversation age.
